Werkzeuge, Connectors, MCP und Skills

Ein Agent wird nützlich, sobald er an deine Systeme kommt. MCP ist der gemeinsame Stecker dafür: Sobald ein Anbieter ihn bereitstellt, kann jedes KI-Tool mit seiner Software sprechen.

Werkzeuge und Connectors geben dem Agenten Hände. Skills geben ihm Erfahrung. MCP macht beides übertragbar.

Jede Anbindung erweitert, was der Agent lesen und tun kann. Darum: so wenig Zugriff wie nötig.

Mehr lesen

Was MCP ist

Das «Model Context Protocol» ist ein offener Standard. Ein System, das ihn spricht, teilt dem KI-Tool mit, welche Werkzeuge es anbietet und wie man sie aufruft: «Kreditor suchen», «Beleg lesen», «Dossier öffnen». Das Modell wählt dann selbst, welches Werkzeug es für einen Auftrag braucht.

Warum das für Fachanwendungen zählt

Heute kommt ein Agent an die meisten Fachanwendungen nur über Umwege: ein Export, eine Datei, ein eigens gebauter Ablauf. Stellt der Hersteller einen MCP-Server bereit, fällt dieser Umweg weg. Die Rechte bleiben dieselben: Der Agent sieht, was das Konto sehen darf, mit dem er angemeldet ist.

Mit wessen Rechten?

Wissen aus SharePoint wird mit den Rechten der fragenden Person abgerufen. Dateien, die direkt in einen Agenten hochgeladen werden, sieht dagegen jede Person, die den Agenten nutzt. Mehr dazu auf der Seite Was die IT freigeben muss.

Lesen, schreiben, auslösen

Lesen ist heikel, Schreiben und Senden noch mehr. Ein Agent, der Mails lesen und versenden darf, kann von einer Mail dazu gebracht werden. Alles, was er liest, kann Anweisungen enthalten, und das Modell kann Material und Befehl nicht sicher unterscheiden. Siehe Risiken.

Skills

Ein Skill ist ein Ordner mit einer Markdown-Datei und, wenn nötig, Vorlagen oder Beispielen. Das Modell liest zuerst nur Name und Beschreibung aller Skills und lädt den ganzen Inhalt erst, wenn die Aufgabe dazu passt. So bleibt das Gespräch schlank. Wie die Bausteine je Plattform heissen, zeigt Gleiche Bausteine, andere Namen.
